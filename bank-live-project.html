DATA MODELING

What If You Have Multiple Tables?

Real projects rarely come as one perfect Excel sheet. You may receive multiple tables from different systems.

Think of it like a school.

Imagine you have one notebook containing student details and another notebook containing exam marks. You don't need to copy the student's name into every marks record. Instead, you connect the two notebooks using a common Student ID.

Transaction_Date

Recommended Modeling Approach

  1. Identify the business process.
  2. Identify the main transaction/fact table.
  3. Identify descriptive dimension tables.
  4. Find primary keys and foreign keys.
  5. Avoid unnecessary duplicate data.
  6. Prefer a clean star-schema structure where appropriate.
  7. Create one-to-many relationships wherever the business logic supports them.
  8. Build a proper Date dimension for time-based analysis.
  9. Avoid unnecessary many-to-many relationships.
  10. Validate totals after relationships are created.

What About Large Datasets?

When the data becomes large, don't blindly load everything into Excel. First understand where the data lives and what information is actually required.

01 Filter unnecessary data early
02 Perform heavy transformations closer to the source where appropriate
03 Use SQL to extract only required data
04 Build a clean analytical model
05 Avoid loading unnecessary columns
06 Validate performance and refresh time
DATA CLEANING

Basic Rules for Cleaning Data

✓ Identify missing values
✓ Remove or investigate duplicates
✓ Correct data types
✓ Standardize text values
✓ Remove unwanted spaces
✓ Validate dates
✓ Check invalid amounts
✓ Check inconsistent categories
✓ Validate primary keys
✓ Validate relationships
✓ Check negative values where inappropriate
✓ Document important assumptions
Remember: Never change a value just because it looks unusual. First understand whether it is genuinely incorrect, a legitimate business value or a data-entry issue.
